# 亿网通IT运维监控管理平台 — 部署与运维手册

> 适用版本：1.0.0 ｜ 更新时间：2026-09-22
> 面向对象：负责现场部署的实施工程师、后续接手运维的技术人员

---

## 一、部署形态

```
                ┌──────────────────────────────────────────┐
   浏览器/大屏 → │  FastAPI (uvicorn)                       │
                │   ├── /            可视化大屏             │
                │   ├── /admin       后台管理              │
                │   ├── /api/v1/*    REST 接口             │
                │   └── /static/*    本地化前端依赖         │
                │  APScheduler 采集调度（同进程）           │
                │  SQLite/MySQL                            │
                └──────────────────────────────────────────┘
                        │ SNMP / SSH / WinRM / ICMP
                        ▼
                 网络设备 / 服务器 / 信创主机
```

**本期为单机 all-in-one 部署**：Web 服务、采集调度、数据库同进程/同机。
这是有意的选择——200 台设备规模下单机毫无压力，拆分只会增加现场实施成本。
为 MySQL 迁移与多 worker 预留的扩展点见 §7。

## 二、环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Linux（Ubuntu 20.04+/CentOS 7+）或 Windows Server 2016+ | 信创环境：麒麟 V10、统信 UOS 均可（纯 Python 实现） |
| Python | **3.10+，推荐 3.12/3.13** | 3.11 及以下需调整 pysnmp/netmiko 版本，见 requirements.txt 注释 |
| 内存 | ≥ 2 GB | 200 台设备 + 3 类日志写入，实测 400 MB 左右 |
| 磁盘 | ≥ 20 GB | metric_sample 明细按天清理（默认保留期见系统配置） |
| 网络 | 可达被监控设备的 161(SNMP)/22(SSH)/5985(WinRM)/ICMP | 平台自身不需要出公网 |

## 三、Linux 部署（推荐）

### 3.1 标准流程（约 10 分钟）

```bash
# 1. 上传代码到 /opt/itsm
cd /opt/itsm

# 2. 建独立虚拟环境（不污染系统 Python）
python3 -m venv venv
source venv/bin/activate

# 3. 安装依赖（内网离线部署见 §3.3）
pip install -r requirements.txt

# 4. 配置环境变量（首次必改三项，见 §5 安全清单）
cp .env.example .env      # 若无此文件，按 §5 手工创建
vim .env

# 5. 初始化数据库（建表 + 管理员账号 + 指标字典）
python scripts/init_db.py            # 已有库不会重复灌数据
# python scripts/init_db.py --demo   # 需要演示数据时（10 台虚拟设备）

# 6. 起服务（前台试跑，确认无报错）
SCHEDULER_ENABLED=true python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 7. 确认健康
curl http://127.0.0.1:8000/api/v1/system/health
#   {"code":0,"data":{"status":"up","database":"ok","scheduler":"running",...}}
```

### 3.2 注册为 systemd 服务（开机自启）

`/etc/systemd/system/itsm.service`：

```ini
[Unit]
Description=亿网通IT运维监控管理平台
After=network.target

[Service]
Type=simple
# ⚠ 用实际部署路径替换 WorkingDirectory / User
WorkingDirectory=/opt/itsm
User=itsm
EnvironmentFile=/opt/itsm/.env
ExecStart=/opt/itsm/venv/bin/python -m uvicorn app.main:app \
    --host 0.0.0.0 --port 8000 --workers 2
Restart=always
RestartSec=5

# ICMP 降级说明：pythonping 需要原始套接字权限。
# 不给 CAP_NET_RAW 时平台会自动降级为系统 ping（不影响功能，只损失逐包 RTT）。
AmbientCapabilities=CAP_NET_RAW

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now itsm
systemctl status itsm          # active (running) 即成功
```

**为什么 `--workers 2` 而不是更多**：采集调度跑在 APScheduler 进程里，
**多 worker 会各起一份调度器导致重复采集**。部署脚本默认 2 个 worker 时，
代码里通过 `SCHEDULER_ENABLED` 环境变量控制只有 worker-0 开调度 ——
若要垂直扩容，先确认这一约定（详见 `.env` 注释）。

### 3.3 内网离线部署（客户现场不通公网）

在有网的同版本机器上把依赖打包成 wheels：

```bash
pip download -r requirements.txt -d wheels/       # 有网机器执行
pip install --no-index --find-links=wheels/ -r requirements.txt   # 现场执行
```

前端依赖（ECharts/Vue）已本地化在 `web/static/vendor/`，随代码一起走，无需额外下载。

## 四、Windows 部署

### 4.1 步骤

```powershell
# 1. 安装 Python 3.12+（勾选 Add to PATH）
# 2. 上传代码到 C:\itsm
cd C:\itsm
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

# 3. 初始化数据库
python scripts\init_db.py

# 4. 试跑
set SCHEDULER_ENABLED=true
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 4.2 注册为 Windows 服务（NSSM）

Python 自带的 `pywin32` 方式在服务账户下经常拿不到环境变量，推荐 NSSM：

```powershell
# nssm.exe 放入 C:\itsm\bin
nssm install ItsMon C:\itsm\venv\Scripts\python.exe "-m uvicorn app.main:app --host 0.0.0.0 --port 8000"
nssm set ItsMon AppDirectory C:\itsm
nssm set ItsMon AppEnvironmentExtra SCHEDULER_ENABLED=true
nssm start ItsMon
```

> WMI 采集（Windows 被监控机）需要 pywinrm 或 WMI 包，
> requirements.txt 已按 `sys_platform == "win32"` 自动处理，无需手工区分。

## 五、配置项（.env）

全部配置**入库或走环境变量，禁止改代码**。核心项：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///./data/itsm.db` | 换 MySQL 只改这一行（见 §7） |
| `SECRET_KEY` | `change-me-in-production` | **生产必改**：JWT 签名密钥 |
| `FERNET_KEY` | 空 | **生产必改**：设备口令/告警密钥的加密密钥；留空时加密功能明确报错而不是静默明文落库 |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 720 | 令牌有效期（12 小时 = 一个班次） |
| `SCHEDULER_ENABLED` | true | 采集调度总开关（排查问题时可临时关掉只保留 Web） |
| `COLLECT_THREAD_POOL_SIZE` | 60 | 采集并发；200 台 / 60 ≈ 4 批完成一轮 |
| `COLLECT_DEFAULT_INTERVAL` | 60 | 默认采集周期（秒），单设备可覆盖 |
| `LOG_LEVEL` / `LOG_KEEP_DAYS` | INFO / 30 | 日志级别与保留天数 |
| `DEMO_MODE` | false | 灌演示数据（演示环境用） |

生成强随机密钥：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"          # SECRET_KEY
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"   # FERNET_KEY
```

> ⚠ **FERNET_KEY 一旦投入使用就不能换**：库里所有设备口令都是用它加密的，
> 换了 key 等于全部口令作废。首次部署前生成好并妥善保管（密码库/纸质密封均可）。

## 六、日常运维

### 6.1 健康检查与自监控

```bash
curl -s http://127.0.0.1:8000/api/v1/system/health
# {"status":"up","database":"ok","scheduler":"running","version":"1.0.0"}
```

- `database=ok`：能连通并有响应
- `scheduler=running`：采集调度活着；`stopped` 说明被 `SCHEDULER_ENABLED=false` 关闭
- **建议把这条接进现有的 Zabbix/监控宝**：探测间隔 60s，失败 3 次告警

数据新鲜度（有没有真的在采）看大屏右上角 `data_fresh_at`，或：

```bash
curl -s http://127.0.0.1:8000/api/v1/dashboard/overview -H "Authorization: Bearer $TOKEN"
```

### 6.2 备份与恢复

```bash
# 每日备份（SQLite 单文件，直接 copy 即可；建议加进 crontab）
#   0 2 * * * sqlite3 /opt/itsm/data/itsm.db ".backup /backup/itsm-$(date +\%F).db"
# ⚠ 不要用 cp 直接拷正在写入的库，可能拿到撕裂的文件；sqlite3 .backup 是在线安全备份。

# 保留 14 天
find /backup -name "itsm-*.db" -mtime +14 -delete
```

恢复：停服务 → 用备份文件覆盖 `data/itsm.db` → 起服务。
**恢复后第一件事**：核对 `FERNET_KEY` 与备份时一致，否则所有设备口令解不开。

### 6.3 日志

| 日志 | 位置 | 用途 |
| --- | --- | --- |
| 应用日志 | `logs/`（按天切割，保留 30 天） | 启动/异常/业务告警 |
| 系统日志 | 界面 → 日志查询 → 系统日志 | 谁在什么时候做了什么操作（审计） |
| 采集日志 | 界面 → 日志查询 → 采集日志 | 每台设备每轮的成功/失败/耗时 |
| 告警日志 | 界面 → 日志查询 → 告警日志 | 触发/恢复/通知/确认全链路 |

### 6.4 常见故障排查

| 现象 | 先查 | 处理 |
| --- | --- | --- |
| 大屏全是"未知"状态 | `system/health` 的 `scheduler` | scheduler=stopped → 检查 SCHEDULER_ENABLED；再看采集日志是否有权限/网络错误 |
| 某台设备一直离线 | 采集日志该设备的 error_msg | SNMP：团体字/防火墙 161；SSH：账号密码/端口；WinRM：TrustedHosts |
| "为什么没收到告警" | 告警中心 → 该事件 → **推送** | 无记录=没到推送环节（静默/收敛限额）；有记录看 success 与渠道返回 |
| 登录报 401 但密码正确 | `.env` 的 SECRET_KEY 是否变过 | 换 SECRET_KEY 会使所有已有令牌失效，重新登录即可 |
| 页面图表空白、控制台报 echarts 404 | `web/static/vendor/` | 部署时漏拷了前端依赖目录 |
| 服务启动 20 秒+ | 首次导入依赖 | 属正常冷启动；稳定后请求毫秒级 |

### 6.5 升级流程

```bash
# 1. 备份数据库（见 6.2）
# 2. 停服务
systemctl stop itsm
# 3. 覆盖代码（保留 .env、data/、logs/、web/static/vendor/）
# 4. 装依赖变更
pip install -r requirements.txt
# 5. 结构变更（本平台用"幂等初始化"，重复执行只补缺失的表/列）
python scripts/init_db.py
# 6. 起服务并看健康
systemctl start itsm && sleep 5 && curl -s localhost:8000/api/v1/system/health
```

## 七、迁移到 MySQL

设计约定：**SQLite ↔ MySQL 只改 `DATABASE_URL`**，不建存储过程/触发器/方言函数。

```bash
# 1. 建库（utf8mb4，别用默认 latin1）
mysql> CREATE DATABASE itsm DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
mysql> CREATE USER 'itsm'@'%' IDENTIFIED BY '<强密码>';
mysql> GRANT ALL ON itsm.* TO 'itsm'@'%';

# 2. 改 .env
DATABASE_URL=mysql+pymysql://itsm:<密码>@127.0.0.1:3306/itsm?charset=utf8mb4

# 3. 初始化 + 迁移历史数据
python scripts/init_db.py
# 历史数据迁移：把 sqlite 库的各表 INSERT 进来即可（表结构与列名完全一致，无外键约束顺序问题）
```

迁移后验证三项：设备列表条数一致、`/dashboard/overview` 数值一致、
触发一次测试告警能正常推送。

## 八、安全清单（上线前逐项打勾）

- [ ] `.env` 的 `SECRET_KEY` 已换强随机值（默认值等于不设防）
- [ ] `FERNET_KEY` 已生成并**离线保管**（丢失=全部设备口令作废）
- [ ] admin 默认密码 `admin123` 已修改；viewer 账号已按值班人员建立
- [ ] 数据库文件权限：`chmod 600 data/itsm.db`（含全部资产与凭据密文）
- [ ] 系统配置里的邮件/企微/钉钉凭据走界面配置（自动加密落库），不写在代码里
- [ ] 大屏账号用 viewer 角色（能看全部、只能确认告警）
- [ ] 8000 端口仅对运维网段开放（防火墙/安全组），不暴露到办公网
- [ ] `/docs` Swagger 在生产可通过环境变量关闭（如需暴露给集成方再开）
