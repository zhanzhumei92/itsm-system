**为什么告警占 65%**：告警是这个系统里唯一"错了用户会立刻知道"的功能
（该报没报 = 故障扩大；不该报乱报 = 狼来了）。采集错一次只是数据少一个点，
告警错一次是丢一次 sleep。用例密度向风险最高的地方倾斜。

## 二、接口端到端回归（107 项）

`scripts/verify_api.py`，进程内 TestClient 直连，覆盖：

| 分组 | 要点 |
| --- | --- |
| 认证 | 登录/错密码 401/无令牌 401/改密码后旧令牌失效 |
| 用户管理 | 增删改查 + 重复账号 1001 + 角色非法 400 + 保护 admin（改角色/禁用/删除 → 1004） |
| 设备管理 | 增删改查、批量启停、连通性测试、**凭据加密落库**、删除级联（凭据/最新值/规则状态清理并返回计数） |
| 资产管理 | CRUD、Excel 导入（含坏表头 1006）、绑定/解绑、维保提醒 |
| 告警全链路 | 建规则 → 灌超标值 → 触发 → 持续 → **确认** → 恢复 → 时间线核对（每一步的状态与时间戳）；**已关闭再确认 → 1005**；不存在 → 404 |
| 指标 | 字典、最新值、**历史曲线降采样**、时间倒置 400、多设备对比、删内置指标 → 1004 |
| 大屏 | 6 个接口 + 字段断言（KPI 结构/趋势分桶/分布中文） |
| 配置/日志/系统 | 配置读写、敏感项掩码、渠道自测、三类日志、健康检查 |
| 脏数据容错 | **手工把库里的枚举字段改成字典外的值**，列表接口必须仍 200（输出侧不挂校验器的守护用例） |

**两个特殊的工程属性**：

1. **可反复执行**：用例自建自清 + 开头 `purge_previous_run()` 清理上次中断残留。
   真实教训：一次中断后垃圾数据让下一次运行第一项就失败，看起来像"权限逻辑回归"，
   实际只是没打扫场地。现在脚本保证幂等，连跑两次结果完全一致。
2. **覆盖度不随运行衰减**：告警段自备"告警中"事件，不依赖上次运行留下的状态。
   （`确认`操作会把 firing 变 acked 且不可逆 —— 若依赖残留状态，同一套用例
   第二次运行时 6 项被静默跳过，通过数从 107 悄悄掉到 101 而失败仍是 0。）

## 三、静态契约检查（8 项，可接 CI）

| # | 检查 | 抓什么 |
| --- | --- | --- |
| 2 | 输出类不得继承带校验器的基类 | 一条枚举外的历史脏数据 → 整个列表接口 500 |
| 3 | raise 的异常类必须已导入 | 代码路径 rarely 走到的分支一执行就 NameError |
| 4 | 路由遮蔽检测 | `/{id}` 吃掉 `/batch-toggle` 这类注册顺序事故 |
| 5 | ORM 唯一约束 ↔ SQL 建表脚本**双向**一致 | 两处定义漂移 → UPSERT 失效、MySQL 静默退化 |
| 6 | METRIC_UNITS ↔ metric_catalog 单位**双向**一致 | 告警通知里"温度 78"没有单位 |
| 7 | 同名字段 description 在输入/输出类之间一致 | 接口文档同一字段两种说法 |
| 8 | 回归脚本 query 参数必须已声明 | FastAPI 静默忽略未声明参数 → 测试"验证不存在的行为" |

**每个检查都注入过人为缺陷验证"真的会报错"**，从未验证过的检查器与从不运行的检查器
在 CI 里长得一样。期间还抓到过一次**假变异测试**（字符串替换没命中却以为验证过了）——
变异测试本身也要先确认真的改到了目标。

## 六、遗留风险与建议（如实列出）

| # | 风险 | 等级 | 建议 |
| --- | --- | --- | --- |
| 1 | 大屏 token 12 小时过期需重新登录 | 低 | 已有 401 浮层就地续期；如现场强烈要求免登录，评估只读 token 方案（见 06 文档待确认项） |
| 2 | `purge_previous_run()` 仅对 SQLite 自动生效 | 低 | MySQL 现场首次跑回归前人工确认清理（函数已做安全跳过） |
| 3 | 多 worker 与调度器的共存约定靠文档约束 | 中 | 二期可加启动锁（数据库锁或文件锁）彻底防重复采集 |
| 4 | 演示数据的采样时间固定 | 信息 | 长期不跑采集后历史曲线窗口内无数据（属预期行为，非缺陷） |
